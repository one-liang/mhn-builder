# 改版與功能規劃

2026-10-21 與維護者逐題確認的決策（Q1–Q35），作為各階段實作與驗收的依據。

**狀態（2026-10-21）**：階段 1–6 與活動裝備補充資料的程式皆已完成並合併到 `develop`。待維護者提供：活動裝備的實際數值（`scripts/sync/config/extra-gear.json`）、遊戲內技能顏色截圖（覆寫 `data/skill-colors.json`）、魔物搜尋別名（`data/monsters.json` 的 `aliases`）。每個階段開一條 `feature/*` 分支，完成後 `git merge --no-ff` 合回 `develop`；要發佈時再走 `release/<版本>` 合到 `main`。

## 自動配裝

- **武器**：先選武器類型（必選）。武器可鎖定（用目前裝備的武器），或由演算法在該類型內挑前 8 名（K=8，與防具相同）。
- **排名**：只看技能覆蓋率，平手比攻擊力；不做 DPS 計算。
- **需強化的武器技能**（`requiredCustomEnhancementLevel`）：視為已解鎖，結果上標示「需強化 Lv N」。
- **漂流石開關**：預設開啟。關閉時完全不分配漂流石，套用方案時保留玩家原有的漂流石，並照 `deserialize()` 的規則截斷超出槽數的部分。
- **效能**：演算法在 Web Worker 執行，計算中顯示 skeleton，可取消。
- **設定保存**：目標技能、武器類型、鎖定武器、漂流石開關存在 localStorage，不寫進分享網址（分享網址只描述配裝結果）。

## 搜尋與魔物

- 合併 `armor-monsters.json` 成一份 `monsters.json`：key、中英文名、別名、頭像。搜尋、篩選、頭像都讀這份。
- 武器 id 帶魔物前綴（如 `kuluyaku_longsword`），可自動對上；對不上的武器在同步報告標為需要人工確認。
- 全站搜尋（頂部搜尋列，手機點放大鏡展開，結果依防具／武器／技能／魔物分組）負責跳頁；列表頁的篩選框就地篩選。兩者共用同一個比對函式：中英文名、套裝名、魔物名與別名，不分大小寫、部分比對。
- 介面只做繁體中文，搜尋同時比對英文。

## 我的配裝

- localStorage 存多組命名配裝（名稱、建立時間、序列化參數），上限 50 組。
- 可改名、刪除、載入；載入沿用 `deserialize()` 的容錯，列表標示「部分裝備已失效」。
- 「我的配裝」頁提供匯出／匯入 JSON 讓玩家換裝置。

## 截圖分享

- 按鈕位置：「目前配裝」卡片與每個自動配裝結果卡片，截的是那張卡片的內容。
- 圖片：直式 1080 寬，含武器、五件防具、漂流石、技能總表、分享連結 QR 碼與站名網址浮水印。
- 先寫入剪貼簿（`navigator.clipboard.write`），失敗或不支援時改為下載。

## 活動裝備（守護者、新年、活動限定）

- 官方網站的 `/zh/armor`、`/zh/weapons` 資料不含這些裝備，現行同步抓不到。
- 新增 `scripts/sync/config/extra-gear.json`：欄位與官方資料相同並通過 `validate:data`，另加 `source: "manual"`；id 加 `ev-` 前綴避免撞名；UI 顯示「非官方資料」標記。
- 先放一筆範例（不顯示在 UI），實際數值待維護者提供。沒有官方圖片時用該系列魔物頭像或通用剪影。
- 官方之後出現同名裝備時，每週同步報告提示改用官方資料。

## 視覺與互動（階段 6）

- Minimalist flat UI，參考 Uber Base：黑白高對比、大量留白、粗體大標題、大圓角。
- Mobile-first、card-based，每個畫面聚焦一個主要動作；手機底部 tab bar：配裝、防具、武器、技能、我的配裝。桌面為置中窄版卡片。
- 首頁 `/` 導向 `/build`，介紹內容縮成配裝頁首次進入的空狀態；漂流石併入「技能」tab（技能｜漂流石切換），`/driftstones` 保留並導向新位置。
- 頁面切換用 View Transitions API（Nuxt `experimental.viewTransition`，不支援的瀏覽器直接切換）；元件用 motion-v 的 spring 動畫；動畫只動 transform／opacity。
- 載入用 skeleton；存檔、刪除等操作採 optimistic UI。
- 深色模式跟隨系統（黑白對調）。
- 字型：Noto Sans TC 900 做大標題，Inter 顯示數字，只載入需要的字重。

### 技能配色

- 官方資料沒有技能顏色，只有五種分類。先依分類給預設色，只用在色點與圖示，文字與卡片維持黑白：

  | 分類 | 色碼 |
  |---|---|
  | 攻擊 `attack` | `#E5484D` |
  | 屬性 `element` | `#3E63DD` |
  | 戰鬥動作 `utility` | `#F5A524` |
  | 防禦 `defense` | `#30A46C` |
  | 耐性／其他 `resistance` | `#8B8D98` |

  （本機 `skills.json` 的分類鍵是 attack／element／utility／defense／resistance，與官方的五類一一對應。）

- `skill-colors.json` 可逐一覆寫單一技能的顏色；維護者提供遊戲截圖後再取色。

## 測試

- Vitest（`npm test`）只測 `app/lib/` 的純邏輯：自動配裝演算法（含武器、漂流石開關）、搜尋比對、存檔序列化與失效偵測。
- UI 不寫自動化測試，用瀏覽器實際操作驗收。
